## 1. Slack CSKH Bot — Socket Mode Integration ✅

### Kiến trúc triển khai
- **Transport:** Slack Socket Mode (không cần public URL/ngrok)
- **NestJS SlackModule:** `apps/api/src/slack/slack.service.ts` — Bolt App kết nối Socket Mode
- **Channel:** `#demo` (ID: `C0C1FFX5N7P`) trên workspace NewVim
- **Credentials:** `SLACK_APP_TOKEN` (xapp-...) + `SLACK_BOT_TOKEN` (xoxb-...)
- **WF05 bị xóa:** Không còn cần "Slack Events Gateway" workflow — Socket Mode thay thế hoàn toàn

### Flow tin nhắn (Slack → Bot → Slack)
```
Khách nhắn #demo
  ↓
NestJS Bolt (Socket Mode) nhận message
  ↓ filter: !bot_id && !subtype && channel_type='channel'
POST /webhook/zalo-webhook → n8n WF04
  ↓ payload: { userId, message, slackChannel, threadTs }
WF04 → Is Bot Active? → CSKH Agent (Gemini) → Parse Output
  ↓
POST /ai-context/outbound-reply → NestJS
  ↓
chat.postMessage(channel, text, thread_ts) → reply trong Slack thread
```

### Thread reply logic
- `threadTs = msg.thread_ts ?? msg.ts` — reply trong cùng thread hoặc tạo thread mới
- Bot reply có `metadata.event_type: 'hr_agent_reply'` → Bolt filter bỏ qua (anti-loop)

### Anti-duplication guard
- Bolt listener filter: `!msg.bot_id && !msg.subtype && msg.channel_type === 'channel'`
- Bot reply metadata: `event_type: 'hr_agent_reply'` được bỏ qua bởi listener

## 2. WF04 — Is Bot Active? Node (Human-in-the-Loop) ✅

### Nodes mới trong WF04
```
Get/Create CSKH Session
  ↓
Is Bot Active? (IF node)
  ├─ TRUE → Save User Message → CSKH Agent → ...
  └─ FALSE → Dừng hoàn toàn (bot im lặng khi escalated)
```

### Escalation flow
1. Khách gửi tin nhắn khiếu nại/kỹ thuật phức tạp
2. CSKH Agent phát hiện → thêm `[CAN_ESCALATE: lý do]` vào cuối reply
3. Parse CSKH Output → `shouldEscalate = true`
4. Should Escalate? → YES → POST `/n8n/escalate` → NestJS:
   - `session.isActive = false`
   - Tạo Notification cho ADMIN
   - WebSocket emit → Portal hiển thị cảnh báo
5. Tin nhắn tiếp theo: `Is Bot Active?` → FALSE → dừng
6. Nhân viên reply từ portal → `POST /agents/chat-session/:id/reply` → Slack thread

## 9. Fix Training Agent không trả về quiz 5 MCQ + 2 tự luận (buổi tối) ✅

### Chẩn đoán (n8n executions 268/269/275)
- **Path chat** (WF01 → WF03 generate_quiz): `Quiz Generator Agent` lỗi **HTTP 503** — model `gemini-3.6-flash` "high demand", node không bật retry → treo ~110s → NestJS cắt 90s → **502 "Không kết nối được AI Agent"** (lỗi user thấy khi chat)
- **Path webhook**: Gemini sinh đúng quiz theo kịch bản NHƯNG `finishReason: MAX_TOKENS` — JSON bị cắt cụt → `JSON.parse` fail → rơi **bộ quiz cứng fallback** (5 câu không dấu về khiếu nại, sai kịch bản)

### Nguyên nhân gốc
1. Model `gemini-3.6-flash` load cao (503) + **không bật retryOnFail**
2. `gemini-2.5-flash` là **model thinking** — thinking token tính vào `maxOutputTokens` → budget 1024/2048 đều cạn trước khi xuất xong JSON

### Fix (đã deploy + verify)
| Thay đổi | Chi tiết |
|---|---|
| **Toàn bộ agent về 2.5-flash** (yêu cầu user) | WF02/03/04: `gemini-3.6-flash` → `models/gemini-2.5-flash` — `scripts/rollback-gemini-model.mjs` |
| WF03 `maxOutputTokens` | 1024 → **8192** (chỗ cho thinking + JSON đầy đủ) — `scripts/fix-wf03-gemini.mjs` |
| WF03 retryOnFail | `true`, maxTries 3, chờ 3s |
| **Verify** | **3/3 scenario** (`colleague_conflict`, `new_employee_onboarding`, `customer_complaint`) sinh quiz thật 5 MCQ + 2 tự luận đúng kịch bản, **hết fallback**; chat path 201 sau 12.5s (hết 502) ✅ |
